# Аудит переноса Yautja по CMSS13

Дата проверки: 2026-07-29.

Сверка выполнялась с локальным снимком `cmss13-ref-full` и текущими прототипами/системами CMU. В рабочем дереве оставлены сторонние пользовательские изменения; этот отчёт описывает только изменения по аудиту.

## Итоговая матрица

| Область | Результат |
| --- | --- |
| Стеклянная химическая посуда корабля | Исправлено; заполнение меняет состояния RSI у большого серебряного стакана и vial, включая размещённые варианты |
| Точки наземной телепортации | 17/17 in-rotation планетных карт имеют уникальную открытую точку; точки отнесены минимум на 8 тайлов от классифицированной человеческой инфраструктуры |
| Дефибриллятор | Обычный дефибриллятор Yautja не воскрешает — как в CMSS13 |
| Оружие | Все основные семейства и прототипы присутствуют; исправлены явные дальности броска |
| Большое/малое самоуничтожение | 600/50 и 800/550; в большом режиме разрушение тайлов принудительно равно 0 |
| Ctrl+Q | Путь `ThrowItemInHand` подключён к `HandsSystem`; Yautja-оружие не блокируется общим `YautjaTechItem` для владельца-Yautja |

## 1. Стеклянная посуда

В оригинале заполнение отображается отдельным слоем с последовательными состояниями RSI. На корабле восстановлена та же схема для:

- `CMUHunterShipSilverCatalystBeaker` — RSI большого стакана `beakerlarge1..5`;
- двух размещённых вариантов серебряного большого стакана — тот же fill-layer и состояния;
- `CMUHunterShipPlacedBaseChemistryEmptyVialVialSouthOffset1x7` — RSI vial `vial1..6`.

Дополнительный аудит проверяет все прототипы с `SolutionContainerVisuals`: настроенные fill-состояния должны существовать в соответствующем RSI, а не только у проверенных сосудов.

Проверка: `YautjaChemistryVisualTest` — 2 passed, 0 failed.

## 2. Наземные точки

Проверены все 17 карт из in-rotation planet roster, включая карты `_CMU14` и связанные `_AU14`, на которых живёт общий CMU-маршрут. Для каждой карты:

- есть `CMUYautjaGroundRelayDestination` с `kind: Ground`;
- UID точки уникален в пределах карты;
- точка лежит на валидном открытом тайле;
- ближайшая классифицированная человеческая инфраструктура находится не ближе 8 тайлов.

Hunting-ground destination markers в эту проверку не смешивались: это отдельный маршрут назначения, а не наземная точка прибытия на планете.

Статическая индексация карт подтверждает 17/17 уникальных точек. Сборка с тестом карт прошла без ошибок, но runtime-тест, загружающий все 17 больших карт, не выдал итог до ограниченного тайм-аута; это следует считать ограничением времени теста, а не подтверждением runtime PASS.

## 3. Дефибрилляция

В исходном CMSS13 `defibrillator.dm` стандартный `check_revive` явно исключает `isyalutja(H)` вместе с не-гуманоидами. В текущем `DefibrillatorSystem` добавлена такая же проверка по `YautjaComponent` до обычного пути оживления.

Регрессионный тест проверяет оба направления: мёртвый Yautja остаётся мёртвым, обычный человек остаётся допустимой целью, а прямой вызов `Zap` также не обходит запрет. Тест: 1 passed, 0 failed.

## 4. Оружие и отличия броска

По исходным классам и текущим прототипам найдены следующие семейства: harpoon, chainwhip, clan/rending/piercing/severing swords, dual/double war scythes, cruel staff, combistick, war axe, ceremonial dagger, shields и shield variants, hunter spear, war/cleaving/ancient glaives, longaxe, duelling blade/club/hatchet/knife, spike launcher, plasma rifle/carbine/pistol, defoliators и fuel tanks, hunting bow, стрелы и варианты стрел, smart disc и wrist/gauntlet weapons.

Явные дальности из `yaut_weapons.dm` теперь перенесены в `ItemThrowRange`:

| Оружие | CMSS13 | Текущий билд |
| --- | ---: | ---: |
| harpoon | 4 | 4 |
| combistick | 4 | 4 |
| war axe | 4 | 4 |
| ceremonial dagger (`/knife`) | 6 | 6 |
| duelling club | 7 | 7 |
| duelling hatchet | 4 | 4 |

Остальные предметы без отдельного `throw_range` используют стандартный путь броска. `ThrowItemInHand` регистрируется в `HandsSystem`, а Yautja-оружие наследует разрешение `YautjaTechItem` для пользователя с `YautjaComponent`; поэтому Ctrl+Q не превращается в запрещённое использование технологии. Для combistick сохранено специальное правило CMSS13: бросок доступен только при заряженном chained-state, после броска заряд расходуется.

Что ещё не является точной 1:1-копией CMSS13:

1. В CMSS13 для части оружия задан `throw_speed = SPEED_VERY_FAST`, а текущий билд использует общий `HandsComponent.BaseThrowspeed`; отдельная скорость на прототип оружия пока не перенесена.
2. Для предметов без явного `throw_range` исходный атомный default равен 7, тогда как текущий общий `HandsComponent.ThrowRange` равен 8. Это касается, например, дуэльного ножа и части оружия без собственного `ItemThrowRange`.
3. Развёрнутые bracer-attached предметы обрабатываются локальной системой вложенного снаряжения: попытка броска отзывает/складывает attachment вместо выпуска его как обычный предмет. Это системное правило вложений, а не потерянный прототип оружия.

## 5. Самоуничтожение

Оригинал использует:

- большой взрыв: `cell_explosion(T, 600, 50, LINEAR)`;
- малый взрыв: `cell_explosion(T, 800, 550, LINEAR)`;
- удалённый thrall-взрыв: `cell_explosion(T, 800, 550, LINEAR)`.

Текущие значения приведены к этим параметрам. Дополнительно `YautjaSelfDestructSystem` передаёт `maxTileBreak: 0` для большого режима независимо от ошибочного/старого значения компонента, поэтому большой взрыв не прорубает тайлы под хищником до космоса. Малый режим сохраняет настроенное значение `SelfDestructMaxTileBreak`; для обычного bracer это 3.

Дефолты `YautjaThrallBracerComponent` также исправлены с 500/65 на 800/550.

Оставшееся отличие: в оригинале большой взрыв выбирается только на ground-level либо при специальном shipside modifier; вне этого условия срабатывает малый профиль. Текущий билд выбирает профиль напрямую через `SelfDestructExplosionType`, без этого контекстного fallback. Это не влияет на требование безопасности тайлов — для Big `maxTileBreak` уже всегда 0 — но остаётся отдельным расхождением параметров/условия выбора.
